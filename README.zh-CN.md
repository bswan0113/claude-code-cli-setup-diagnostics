## 下载 Windows x64 版

| 版本 | 用途 | 下载 |
|---|---|---|
| **完整版** | 安装和修复 Claude Code，管理会话和账户，并使用侧边栏。 | [ClaudeLauncher.exe](https://github.com/bswan0113/claude-code-cli-setup-diagnostics/releases/latest/download/ClaudeLauncher.exe) |
| **安装和修复专用 Mini** | 打开后直接开始诊断。查看原因和建议操作，确认后再执行安装或修复。 | [ClaudeRepairMini.exe](https://github.com/bswan0113/claude-code-cli-setup-diagnostics/releases/latest/download/ClaudeRepairMini.exe) |

选择一个可执行文件，下载后即可打开。两个版本都无需另行安装 .NET。界面语言可选英语、韩语、简体中文或日语。

完整版可以在 Windows 上安装或修复 Claude Code CLI，也可以打开以前的会话继续工作。

1. **安装和修复 Claude Code CLI。** 首次使用时可安装 CLI。如果无法启动，可以运行八步诊断，查看原因和修复方法。启动器会先列出要做的更改，等你确认后再执行。
2. **查找并继续本机的 Claude Code 会话。** 在启动器中可以按项目文件夹浏览本机保存的 Claude Code 会话记录。选中会话后，启动器会在原工作目录打开 PowerShell，让你在 CLI 中继续上次的对话。

## 安装和修复

Mini 会在打开 `ClaudeRepairMini.exe` 后立即开始检查，并在第一个画面显示结果。如果发现问题，会说明原因和建议的修复方式，并询问是否继续。

在完整版中，点击主窗口顶部或侧边栏左下角的**安装和修复**后，启动器会自动检查。结果分为「需要安装」「发现问题」和「未发现问题」。发现问题时，状态会以红色突出显示。

如果能自动修复，启动器会说明原因，推荐一项操作，并询问是否继续。选**是**执行这项操作，选**否**则保留现有设置。需要自行登录或联系管理员时，结果中会给出下一步。想查看检查依据时，可以展开「完整诊断结果」，查看八个步骤的详情。

| 步骤 | 检查内容 | 处理方法 |
|---|---|---|
| 1. 电脑环境 | Windows 内部版本和体系结构、Windows PowerShell 的版本和路径，以及用户目录中的空格和非 ASCII 字符。 | 确认系统支持 x64 并检查 PowerShell 路径。用户目录中的空格或中文等字符仅作提示。 |
| 2. 可执行文件 | 已知安装位置、发布者签名、版本、更新留下的 `.new.*` 和 `.old.*` 备份，以及旧版本文件。 | 优先从已验证的备份恢复。可执行文件缺失且没有可用备份时，启动器会建议使用官方 PowerShell 安装程序。如果需要关闭 Claude 才能替换文件，请先核对进程 PID。结束进程会中断该会话。 |
| 3. PATH | 对比启动器当前使用的 PATH、Windows 保存的用户和系统 PATH，以及 CLI 的实际位置。 | 将已验证的安装目录添加到用户 PATH。如果已经添加，刷新启动器的 PATH，让新打开的 PowerShell 使用该路径。 |
| 4. 重复安装与命令冲突 | 同名可执行文件、npm 全局包、WindowsApps 别名和旧版安装目录 `.claude\local`。 | 调整用户 PATH 的顺序，让可用版本优先启动。卸载重复的 npm 包和清理旧文件需分别确认。清理旧版安装时，只会删除确认窗口列出的普通文件。 |
| 5. PowerShell 执行策略 | 当前策略是否阻止 npm 安装的 PowerShell 脚本，以及组织是否管理这些策略。 | 如果仅修改用户设置就能解决，可以将 `CurrentUser` 的执行策略设为 `RemoteSigned`。如果组织策略生效，请联系管理员或使用原生 CLI。 |
| 6. 身份验证、证书、Git 与代理 | 检查 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL` 的作用域，`NODE_EXTRA_CA_CERTS` 指向的证书文件，`CLAUDE_CODE_GIT_BASH_PATH` 指向的程序，以及 Git 安装和代理设置。界面会隐藏凭据和代理地址的具体值。 | 先确认公司或课程对设置的要求。可以逐个删除多余的用户变量，也可以把失效的 Git Bash 路径改为检查时找到的路径。系统变量和组织管理的设置请向管理员确认。 |
| 7. 网络 | 检查下载响应以及与 Claude 网站的连接。设置 API 密钥后，还会检查默认 API 服务器。 | 根据出错的服务和错误信息检查证书、代理、防火墙或网络连接。收到 API 的 HTTP 响应说明服务器可达，登录状态由快速检查单独确认。 |
| 8. 更新清理 | 检查残留的 `claude.exe.old.*`、`.new.*`、`.broken.*` 文件、`.claude\downloads` 缓存和当前用户的自动更新设置。 | 分别核对残留文件和下载缓存的清单后再删除。清理时会保留最新的 old 备份。如果因原生安装更新损坏而关闭自动更新，今后需要手动更新。 |

**如果 `~/.local/bin/claude.exe` 丢失**，启动器会查找其他可用的安装，并检查其 PATH。如果找不到可执行文件，但有通过验证且可用的备份，启动器会推荐一个备份，并询问是否将它恢复到原路径。如果没有可用的备份，启动器会询问是否使用 Anthropic 官方 PowerShell 安装程序重装 CLI。

如果 `claude.exe` 还在，启动器会区分签名哈希不符、缺少签名、发布者不符、无法确定信任状态，以及签名有效但版本检查失败。启动器会阻止运行签名缺失、不符或无法确认的文件。如果受影响的是当前用户的原生可执行文件，且已验证的 Anthropic 备份可安全恢复到同一路径，点击**是**会单独保留当前文件，再恢复备份。若没有可用备份，且已确认可安全保留此原生文件，请关闭 Claude Code，将文件改为尚未使用的名称（如 `claude.exe.saved`），再检查能否运行官方安装程序。WinGet 等工具管理的文件应保留在原位置，请检查相应工具和 PATH。若检查结果不一致或无法确认签名，请核对读取权限后重新检查。

默认检查 `downloads.claude.ai` 和 `claude.ai`。仅当启动器环境中的 `ANTHROPIC_API_KEY` 非空且使用默认 API 地址时，才会向 `api.anthropic.com` 发送匿名请求。如果公司使用代理或内部 CA 证书，请和网络管理员一起核对结果。[Anthropic 网络配置说明](https://code.claude.com/docs/en/network-config)

### 设置文件、Defender 和修复记录

第 6 步按 UTF-8 JSON 检查 `~/.claude.json` 和 `~/.claude/settings.json`。文件可以不存在。语法错误会标出行号和列号。如果补上一个缺少的逗号，或删去一个末尾多余的逗号，就能让整个文件通过检查，启动器会建议只修正这一处。其他情况会查找格式相符的备份，并尝试恢复损坏的部分。如果需要替换整个文件，预览会明确说明。确认前请查看已遮盖敏感值的差异和原文件的保留位置。

撤销设置修复会恢复修复前的原文件，其中也包括原有的 JSON 错误。启动器会先核对修复后的文件和保留的原文件，两者的哈希都与记录一致时才恢复。任一文件有变动就会停止撤销。

如果 CLI 可执行文件丢失，第 2 步会查找与已知安装路径相符的 Microsoft Defender 隔离记录。无法读取记录或没有匹配项时，隔离仅列为可能原因。可以打开 Windows 安全中心的**保护历史记录**，自行查看和处理。

如果修复记录表明自动更新是由启动器关闭的，且当前用户设置仍与记录相符，第 8 步可以恢复此前的设置。对原本就存在的用户变量 `DISABLE_AUTOUPDATER`，如果与系统、进程或组织策略没有冲突，也可以单独批准清除。

修复记录保存在 `%LOCALAPPDATA%\ClaudeCodeSetupDiagnostics\repair-history`，使用当前 Windows 账号的 DPAPI 加密。撤销 PATH 更改、用户执行策略、更新设置或已记录版本的 npm 包移除时，启动器会先核对当前状态。恢复 npm 包需要记录中的版本和安装前缀、通过验证的工具以及网络连接。删除文件和结束进程只留记录，无法撤销。

### 安装和登录

- 在你选**是**之前，启动器会说明先使用 Anthropic 官方 PowerShell 安装程序，以及在什么条件下会改用 WinGet。本次确认也包括满足条件时使用 WinGet。
- 如果需要登录，选**是**即可打开单独的 PowerShell 窗口。启动器使用已验证的 CLI 执行 `claude auth login`。在浏览器中完成登录，或关闭登录窗口取消。两种情况下启动器都会重新检查账号状态。
- Git for Windows 可以按需安装。如果未安装 Git 且能找到 Microsoft 注册的 WinGet，第 6 步会提供为当前 Windows 用户安装 `Git.Git` 的选项。核对安装目标后，单独确认这项操作。确认安装也表示同意 WinGet 源和 Git 软件包的条款。
- 如果你是在打开会话时进入修复界面的，修复后的快速检查通过后，可以返回原来的目录和会话。

| 遇到的问题 | 下一步 |
|---|---|
| 无法打开工作目录 | 确认目录是否已移动或删除，用**浏览文件夹**选择当前位置。 |
| PowerShell 找到了其他安装版本 | 在同一目录运行 `Get-Command claude -All` 查看命令顺序。启动器会先验证原生可执行文件的 Authenticode 签名和发布者 `Anthropic, PBC`，再查询版本。 |
| 安装看起来停住了 | 下载期间可能没有输出。启动器会同时监测安装程序的输出和下载文件的变化。只有两者连续 5 分钟都没有变化，且原安装进程已安全终止，才会尝试 WinGet。安装出错、用户取消或安装后验证失败时，不会改用 WinGet。 |
| 诊断用的 PowerShell 无响应 | 快速检查中的每次 PowerShell 检测最多等待 25 秒。查看弹窗中的错误和退出代码，然后在受影响的目录打开 PowerShell。 |

你同意安装或重新安装后，启动器会在 PowerShell 中运行以下官方命令。[Anthropic 官方安装指南](https://code.claude.com/docs/en/setup#install-claude-code)

```powershell
irm https://claude.ai/install.ps1 | iex
```

## 管理会话

1. 在 Windows x64 上打开 `ClaudeLauncher.exe`。可执行文件已包含 .NET 桌面运行时。
2. 在**正在运行**中点击**切换**即可返回已打开的终端。**最近运行的会话**最多显示五个会话。
3. 在**文件夹与会话**中展开项目目录，或按会话名称搜索。选中会话后，启动器会在对应目录运行 `claude --resume <session-id>`。要开始新的对话，可以点击**开始新会话**，也可以输入其他目录的路径。
4. 如果某个目录的记录无法读取，点击**在 CLI 中选择此文件夹的会话**，即可在 PowerShell 中通过 `claude -r` 选择会话。右键点击目录树可手动指定文件夹。

会话标题和目录来自 Claude 配置目录下 `projects` 中的 JSONL 文件。如果启动器没有该会话的运行记录，就按文件最后修改时间排序。

在**文件夹与会话**旁的排序菜单中，可以按最近运行时间、文件夹名称或完整路径升序或降序排列文件夹。默认将最近运行的文件夹排在最前，修改后下次启动仍会沿用。侧边栏会在文件夹名称下方显示路径。如果路径被省略，将鼠标指针移到路径上即可查看完整内容。

### 账户标签

点击启动器顶部的 **＋**，输入标签名称，再选择**创建并登录**。在新配置中通过 PowerShell 和浏览器完成 Claude Code 登录。如果中途关闭了登录窗口，可点击**登录**重试。标签显示你输入的名称。

点击标签后，同一窗口会显示该账户的项目、最近会话和正在运行的终端。默认账户使用原有的 Claude Code 配置。新增的配置使用各自的 `CLAUDE_CONFIG_DIR` 存储设置和本地会话记录。正在启动或已经打开的终端继续使用原账户。登录、移除或恢复会话时，请等操作完成后再切换。如果安装和修复面板已打开，请先关闭。

默认标签使用启动时指定的配置目录或 `~/.claude`。新增配置使用 `%LOCALAPPDATA%\BlsLab\ClaudeLauncher\profiles\<ID>\claude`，Claude Code 也会在此保存该账户的登录信息。各标签共用 CLI 安装和 Windows 用户 PATH。项目设置和组织策略仍然适用。 [Claude Code 多账户登录](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)

将鼠标悬停在会话的词元用量上，可查看记录中经过遮盖的所有者账户 ID。只有一个配置与该 ID 匹配时才会显示其标签名称。如果只有产物活动记录提供线索、缺少记录或 ID 相互冲突，启动器不会推断所有者。

### 移除和恢复本地记录

点击文件夹排序菜单旁的**管理**，可以勾选多个项目或会话。展开项目可逐个选择会话。勾选整个项目时，会包含该文件夹下保存的全部会话，包括搜索时隐藏的会话。只移除一项时，可打开这一行的 **⋯** 菜单，或用键盘选中该行并按 **Delete**。确认窗口会列出完整路径和会话数。所选项目或会话若在终端中打开或正在启动，请先关闭。

移除项目会从启动器列表中移除该项，并将其本地会话记录移到**启动器回收站**。没有会话的项目也可移除。工作文件夹和文件、单列为项目的子文件夹、提示词历史、独立的子代理日志和云端数据都会保留。重启后仍可通过**管理 → 启动器回收站**恢复。一次移除的项目和会话会一起恢复。如果目标位置已有文件，启动器会停止恢复。

会话列表会过滤 Claude 为每个会话创建的临时 `scratchpad` 目录，以及标记为子代理的会话记录。

### 词元用量

文件夹显示其中所有会话已记录的词元总数，包括被搜索条件隐藏的会话。每个会话的总数是输入词元（含缓存读写）与输出词元之和。这些数字来自本机的主会话记录，不包含单独保存的子代理记录或服务商的账单数据。

**上下文**显示最近一次记录的上下文词元数及其占窗口容量的百分比。带 `≈` 的百分比按模型的默认窗口大小估算。短横线表示数值未知，`≥` 表示只汇总了部分记录。只有会话中记录过压缩，才会显示压缩次数。K 表示千，M 表示百万。将鼠标移到用量上可查看具体数值。

## 外观设置

拖动 Windows 标题栏可以移动侧边栏，拖动边框或任一角可以调整大小。点击标题栏的 × 或按 Alt+F4 即可退出启动器。下次打开时，侧边栏会恢复到上次的显示器、位置和大小。

将窗口停靠在屏幕左侧或右侧即可作为侧边栏使用。在**外观设置**中可以启用深色模式、调整字号（85% 至 125%）和窗口不透明度（60% 至 100%）。主窗口和侧边栏共用这些设置，下次启动时会保留。界面支持英语、韩语、简体中文和日语。

## 从源码构建

在安装了 .NET 10 SDK 的 Windows 上，从仓库根目录运行所需版本的命令。

```powershell
# 完整版
dotnet publish src/ClaudeLauncher.csproj -c Release -r win-x64 -p:PublishProfile=Windows-x64

# 安装和修复专用 Mini
dotnet publish src/Mini/ClaudeRepairMini.csproj -c Release
```

输出目录为 `artifacts/publish/win-x64/`。完整版会生成 `ClaudeLauncher.exe`，Mini 会生成 `ClaudeRepairMini.exe`。
