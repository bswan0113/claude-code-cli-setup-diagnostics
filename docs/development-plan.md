# 개발 계획과 담당 채팅

2026-11-24 Windows x64 개발 빌드. 첫 화면에서 대화를 이어 열거나 새 작업 폴더를 선택한다. 런처, 진단, GUI 담당이 구현하고 코드 리뷰와 QA는 각각 독립 채팅에서 검증한다. [사용자 흐름과 상세 분기](workflow.md)

## 이번 빌드에서 확인한 동작

단일 EXE를 열고 합성 기록의 첫 사용자 메시지를 클릭했다. 런처가 연 PowerShell에서 서명된 Claude CLI 프로세스에 선택한 세션의 정확한 GUID가 `--resume` 인수로 전달됐다. 손상 기록 선택기에서도 `-r` 전달을 확인했다. 손상 파일에서 폴더를 알아낸 경우에는 경로를 다시 입력하지 않고 그 폴더 버튼을 눌러 선택기를 열었다. 이 검증은 개발 PC에서 수행했다. 깨끗한 Windows에서의 첫 설치와 사용자 계정 로그인은 별도 인수 항목이다.

## 구현 순서와 완료 기준

| 순서 | 작업 | 완료를 확인하는 방법 |
|---|---|---|
| 1. 공통 계약 | 헤드가 솔루션 구조와 경로·진단·실행 결과 형식을 정한다. 폴더 선택부터 같은 폴더에서 재실행할 때까지 한 요청으로 추적한다. | 정상 실행, 경로 오류, PATH 복구, 조치 취소의 예시 데이터를 세 담당이 같은 의미로 해석한다. |
| 2. 병렬 구현 | 런처는 실제 PowerShell을 열고, 진단은 같은 셸의 명령 해석을 조사한다. GUI는 네 언어로 홈과 진단 결과를 표시한다. | 경로에 한글·공백·대괄호·앰퍼샌드가 있어도 선택한 폴더에서 키보드 입력이 된다. 진단은 정상 설치와 미설치 추정을 구분한다. |
| 3. 첫 통합 | 세 모듈을 연결한다. 경로가 올바르고 CLI가 작동하는 사용자는 전체 검사 없이 곧바로 작업한다. | 기존 사용자와 첫 사용자 모두 폴더를 열 수 있다. 정상 종료·사용자 취소·관측할 수 없는 창 닫힘이 자동 복구로 이어지지 않는다. |
| 4. 설치와 복구 | 동의를 받은 뒤 공식 설치 또는 사용자 PATH 추가를 수행한다. 갱신된 환경에서 명령 해석과 버전을 확인한 후 같은 폴더에서 한 번 재실행한다. | 정상 설치를 중복 설치하지 않는다. 설치 중단 후 다시 열면 현재 상태부터 확인한다. 재시도 실패 시 오류를 보여주고 멈춘다. |
| 5. 배포 검수 | 우선 Windows 11 x64, 일반 사용자 계정, .NET Desktop Runtime이 없는 환경에서 자체 포함 WPF EXE를 검수한다. | 최신 패키지만 받아 새 설치·정상 실행·PATH 복구를 끝까지 수행한다. 네 언어에서 버튼, 오류, 재시도, 키보드 탐색, 긴 경로와 화면 배율을 확인하고 배포 파일의 버전과 체크섬을 기록한다. |

## 세 영역을 연결하는 값

- 세션 목록은 설정 디렉터리의 `projects` 아래 주 세션 JSONL에서 첫 사용자 메시지, 파일 수정 시각, 세션 ID, 작업 폴더를 읽는다. 사용자 지정 `CLAUDE_CONFIG_DIR`도 지원한다. 런처 자체 이력은 별도로 저장한다. 인덱스를 읽지 못하면 CLI의 선택기로 넘긴다.
- 같은 세션 ID의 복사본은 정상적으로 읽힌 기록을 우선하며, 판독 상태가 같으면 수정 시각이 가장 최근인 기록을 사용한다. 제목과 작업 폴더를 얻기 전에 1 MiB를 넘는 JSONL 행을 만나면 그 행을 건너뛴다. 사용할 수 있는 정상 복사본이 없으면 Claude CLI 선택기에서 해당 세션을 찾을 수 있다.
- 런처는 경로를 프로세스 작업 디렉터리로 전달한다. 사용자가 입력한 경로를 셸 명령문에 붙이지 않는다. 정상 실행 전에는 선택한 셸에서 실제 호출할 CLI를 식별한다. 셸 시작, CLI 시작 실패, 종료 코드, 관측 중단을 구분한다. PowerShell 창이 뜬 시점에는 ‘PowerShell 열림’까지만 표시한다.
- 진단 결과는 실패 단계, 관측 근거, 원인 확정 여부, 제안할 조치와 변경 범위를 담는다. PATH 문제가 의심되면 같은 셸의 명령 해석과 확인된 실행 파일의 직접 실행을 비교한다. 공식 로그인 또는 사용자의 수동 조치가 필요한 상태는 버튼을 따로 둔다.
- GUI는 결과 코드와 값을 받아 `ko`, `en`, `zh-Hans`, `ja` 리소스로 표시한다. 언어는 사용자 선택, Windows 표시 언어, 영어 순으로 결정한다. 전환 후에도 선택한 폴더와 진행 상태를 유지한다.

## 첫 배포 범위와 남은 검증

첫 배포 후보는 Windows 11 x64용 자체 포함 WPF 실행 파일이다. 중국어는 간체로 시작한다. ARM64 패키지는 해당 장비에서 검증한 뒤 지원 범위를 정한다. 서명 여부와 공개 배포 경로는 출시 전에 확정한다.

별칭·중복 설치, 인증 오류, 연결 실패는 원인을 확인할 수 있는 범위에서 안내한다. 손상된 백업 교체, npm 사본 삭제, 실행 정책 변경, 보안 설정 변경은 첫 자동 복구 범위 밖이다. 출시 전 가장 먼저 실험할 부분은 일반 터미널의 입력을 유지하면서 CLI 시작 실패와 사용자의 정상 종료를 얼마나 정확히 구분할 수 있는지다. [Anthropic 설치 안내](https://code.claude.com/docs/en/setup)
