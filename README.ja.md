## Windows x64 版をダウンロード

| エディション | 用途 | ダウンロード |
|---|---|---|
| **フル版** | Claude Code のインストールと修復、セッションやアカウントの管理、サイドバーを利用できます。 | [ClaudeLauncher.exe](https://github.com/bswan0113/claude-code-cli-setup-diagnostics/releases/latest/download/ClaudeLauncher.exe) |
| **インストール・修復専用 Mini** | 起動するとすぐに診断が始まります。原因と対処方法を確認し、承認するとインストールや修復を実行します。 | [ClaudeRepairMini.exe](https://github.com/bswan0113/claude-code-cli-setup-diagnostics/releases/latest/download/ClaudeRepairMini.exe) |

使いたい方の実行ファイルをダウンロードして開いてください。どちらも .NET を別途インストールする必要はありません。画面の言語は英語・韓国語・中国語（簡体字）・日本語から選べます。

フル版では、Windows で Claude Code CLI をインストール・修復し、以前のセッションを開いて作業を再開できます。

1. **Claude Code CLI のインストールと修復。** 初めて使うときは CLI をインストールできます。起動できないときは、8 ステップの診断で原因と対処方法を確認できます。変更を加える前に、ランチャーが実行内容を表示して確認を求めます。
2. **ローカルの Claude Code セッションを探して再開。** ランチャーでは、この PC に保存された Claude Code の会話を作業フォルダー別に探せます。セッションを選ぶと、そのフォルダーで PowerShell が開き、CLI で会話の続きを始められます。

## セットアップと修復

Mini は `ClaudeRepairMini.exe` を開くと診断を開始し、最初の画面に結果を表示します。問題があれば原因と対処方法を示し、修復を進めるか確認します。

フル版では、メイン画面の上部またはサイドバーの左下で **セットアップと修復** を開くと、診断が自動で始まります。結果は「インストールが必要」「問題あり」「問題なし」のいずれかです。問題がある場合は赤で表示します。

修復できる問題があれば、ランチャーが原因と推奨する操作を一つ示し、実行するか尋ねます。**はい** を選ぶとその操作を実行し、**いいえ** を選ぶと変更しません。ログインや管理者への問い合わせが必要な場合は、次の手順が表示されます。判定の根拠を見たいときは「診断結果の詳細」を展開すると、全 8 ステップの結果を確認できます。

| ステップ | 確認する項目 | 対処方法 |
|---|---|---|
| 1. PC 環境 | Windows のビルドとアーキテクチャ、Windows PowerShell のバージョンとパス、ユーザーフォルダー名の空白や非 ASCII 文字。 | x64 の実行環境と PowerShell のパスを確認します。フォルダー名に空白や日本語などの文字がある場合は、参考情報として表示します。 |
| 2. 実行ファイル | 既知のインストール先、発行元署名、バージョン、更新時に残った `.new.*` と `.old.*` のバックアップ、旧バージョンのファイル。 | 検証済みのバックアップがあれば復元を優先します。実行ファイルがなく、使えるバックアップもない場合は、公式の PowerShell インストーラーを案内します。ファイルの置き換えに Claude の終了が必要な場合は、対象プロセスの PID を確認してください。終了すると、そのセッションの作業が中断します。 |
| 3. PATH | ランチャーの現在の PATH、Windows に保存されたユーザーとシステムの PATH、CLI の実際の場所。 | 確認済みのインストール先をユーザー PATH に追加します。登録済みならランチャーの PATH を再読み込みして、次に開く PowerShell に反映します。 |
| 4. 重複インストールとコマンドの競合 | 同名の実行ファイル、npm のグローバルパッケージ、WindowsApps のエイリアス、旧版の `.claude\local` フォルダー。 | 正常なインストール先が優先されるようにユーザー PATH の順序を変えられます。重複する npm パッケージの削除と旧版ファイルの削除は個別に実行します。旧版の整理では確認画面に表示された通常ファイルだけを削除します。 |
| 5. PowerShell の実行ポリシー | npm で導入した PowerShell スクリプトがポリシーでブロックされているか、組織がポリシーを管理しているか。 | ユーザー単位で解決できる場合は `CurrentUser` の実行ポリシーを `RemoteSigned` に変更できます。組織のポリシーが適用される場合は、管理者に相談するかネイティブ CLI を使います。 |
| 6. 認証・証明書・Git・プロキシ | `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL` の設定範囲、`NODE_EXTRA_CA_CERTS` の証明書ファイル、`CLAUDE_CODE_GIT_BASH_PATH` のシェルパス、Git とプロキシの設定。認証情報の値やプロキシのアドレスは画面に表示しません。 | 職場や研修で必要な設定かどうかを確認します。不要なユーザー変数は個別に削除できます。Git Bash のパスが無効なら、検出したシェルのパスに変更できます。システム変数や管理対象の設定は管理者に確認してください。 |
| 7. ネットワーク | ダウンロードの応答と Claude のウェブサイトへの接続を確認します。API キーを設定した場合は、既定の API サーバーへの接続も確認します。 | 接続先とエラーを手掛かりに証明書、プロキシ、ファイアウォール、回線を確認します。API の HTTP 応答から分かるのはサーバーに到達したかどうかです。ログイン状態は簡易診断で確認できます。 |
| 8. 更新ファイルの整理 | 残った `claude.exe.old.*`、`.new.*`、`.broken.*`、`.claude\downloads` のキャッシュ、現在のユーザーの自動更新設定。 | 残ったファイルとダウンロードキャッシュは、それぞれ対象一覧を確認してから削除します。最新の old バックアップは残ります。ネイティブ版の更新に失敗して自動更新を無効にした場合は、以後手動で更新してください。 |

**`~/.local/bin/claude.exe` が消えた場合**、ランチャーは別の場所に正常なインストール先があれば、その PATH を確認します。実行ファイルが見つからず、復元に使える検証済みのバックアップがあれば、一つ選んで元の場所に復元するか尋ねます。使えるバックアップがなければ、Anthropic 公式の PowerShell インストーラーで再インストールするか尋ねます。

`claude.exe` がある場合は、署名時からの内容の変化、署名なし、発行元の相違、信頼性を判定できない状態、有効な署名があってもバージョン確認に失敗した状態を区別します。署名がない場合や、署名が一致しない場合、信頼性を確認できない場合は実行を止めます。対象が現在のユーザーのネイティブ実行ファイルで、同じ場所に安全に戻せる Anthropic のバックアップを検証できた場合は、**はい** を押すと元のファイルを別に保管してバックアップを復元します。使えるバックアップがなく、ネイティブ実行ファイルを安全に退避できると確認できた場合は、Claude Code を閉じます。ファイルを `claude.exe.saved` など未使用の名前に変えて保管し、再検査すると公式インストーラーを使用できるか確認できます。WinGet など別のツールが管理するファイルは移動せず、そのツールと PATH を確認してください。検査結果が食い違う場合や署名を判定できない場合は、アクセス権限を確認して再検査してください。

通常は `downloads.claude.ai` と `claude.ai` に接続します。ランチャーの環境で `ANTHROPIC_API_KEY` に値があり、既定の API URL を使う場合に限り、`api.anthropic.com` に匿名で接続します。社内プロキシや独自の CA 証明書を利用している場合は、診断結果をネットワーク管理者と確認してください。[Anthropic のネットワーク設定ガイド](https://code.claude.com/docs/en/network-config)

### 設定ファイル、Defender、修復履歴

ステップ 6 では `~/.claude.json` と `~/.claude/settings.json` を UTF-8 の JSON として確認します。ファイルがなくても問題ありません。構文エラーがあれば行と列を表示します。不足しているカンマを一つ補うか、末尾の余分なカンマを一つ取り除くだけでファイル全体が有効になる場合は、その修正を提案します。それ以外は形式の合うバックアップを探し、破損した部分の復元を試みます。ファイル全体の置き換えが必要な場合はプレビューに表示されます。機密値を伏せた差分と元のファイルの保存先を確認して承認してください。

設定の修復を取り消すと、JSON のエラーも含めて元のファイルに戻ります。ランチャーは修復済みのファイルと保管した元のファイルのハッシュをそれぞれ記録と照合し、両方が一致する場合にだけ元に戻します。

CLI の実行ファイルが見つからない場合、ステップ 2 では既知のインストール先に一致する Microsoft Defender の隔離記録を調べます。記録を読めない場合や一致する検出がない場合、隔離は考えられる原因として表示されます。Windows セキュリティの **保護の履歴** を開き、必要な対応を選んでください。

ステップ 8 では、ランチャーが自動更新を無効にした履歴があり、現在のユーザー設定が記録と一致する場合に元の設定に戻せます。もともとユーザーに設定されていた `DISABLE_AUTOUPDATER` は、システムやプロセスの設定、組織のポリシーと競合しなければ、個別に承認して解除できます。

修復履歴は `%LOCALAPPDATA%\ClaudeCodeSetupDiagnostics\repair-history` に保存され、現在の Windows アカウントの DPAPI で暗号化されます。PATH、ユーザーの実行ポリシー、更新設定の変更、およびバージョンが記録された npm パッケージの削除は、現在の状態を確認してから元に戻せます。npm パッケージの復元には記録済みのバージョンとインストール先、検証済みのツール、ネットワーク接続が必要です。ファイル削除やプロセス終了は履歴で確認できますが、取り消すことはできません。

### インストールとログイン

- **はい** を押す前に、Anthropic 公式の PowerShell インストーラーを使うことと、WinGet に切り替える条件が表示されます。この条件を満たした場合の WinGet の実行も、同じ確認に含まれます。
- ログインが必要な場合は **はい** を選ぶと、別の PowerShell ウィンドウが開きます。ランチャーは検証済みの CLI で `claude auth login` を実行します。ブラウザーでログインを完了するか、ログイン画面を閉じてキャンセルしてください。どちらの場合もランチャーがアカウントの状態を再確認します。
- Git for Windows の導入は任意です。Git がなく、Microsoft が登録した WinGet が見つかる場合、ステップ 6 から現在の Windows ユーザーに `Git.Git` をインストールできます。対象を確認し、この操作を個別に承認します。インストールの承認には、WinGet ソースと Git パッケージの利用条件への同意が含まれます。
- セッションを開く途中で修復画面に入った場合は、修復後の簡易診断が正常なら、最初に選んだフォルダーとセッションに戻れます。

| 症状 | 確認すること |
|---|---|
| 作業フォルダーが開かない | 移動または削除されていないか確認し、**フォルダーを参照** から現在の場所を選びます。 |
| PowerShell が別のインストール先を参照する | 同じフォルダーで `Get-Command claude -All` を実行し、コマンドの優先順位を確認します。ランチャーはネイティブ実行ファイルの Authenticode 署名と発行元 `Anthropic, PBC` を検証してからバージョンを取得します。 |
| インストールが止まって見える | ダウンロード中は何も表示されないことがあります。ランチャーはインストーラーの出力とダウンロードファイルの変化を監視します。どちらも 5 分間途絶え、元のインストールプロセスを安全に終了できた場合に限り、WinGet を試します。インストールエラー、キャンセル、インストール後の検証失敗では WinGet に切り替わりません。 |
| 診断用の PowerShell が応答しない | 簡易診断は PowerShell の確認 1 回につき最大 25 秒待ちます。ダイアログのエラーと終了コードを確認し、対象フォルダーで PowerShell を開いてください。 |

新規インストールと再インストールでは、承認後に次の公式コマンドを PowerShell で実行します。[Anthropic の公式インストールガイド](https://code.claude.com/docs/en/setup#install-claude-code)

```powershell
irm https://claude.ai/install.ps1 | iex
```

## セッションの管理

1. Windows x64 で `ClaudeLauncher.exe` を開きます。.NET デスクトップランタイムは実行ファイルに含まれています。
2. 開いているターミナルに戻るには **実行中** で **切り替え** を選びます。**最近実行したセッション** には最大 5 件表示されます。
3. **フォルダーとセッション** でプロジェクトのフォルダーを展開するか、セッション名で検索します。セッションを選ぶと、そのフォルダーで `claude --resume <session-id>` が実行されます。新しい会話は **新しいセッションを開始** から開けます。別のフォルダーのパスも入力できます。
4. 履歴を読み取れないフォルダーでは **CLI でこのフォルダーのセッションを選ぶ** を押すと、PowerShell で `claude -r` の一覧が開きます。フォルダーを直接指定するにはツリーを右クリックしてください。

タイトルと作業フォルダーは、Claude の設定ディレクトリにある `projects` 配下の JSONL ファイルから読み取ります。ランチャーに起動履歴がないセッションは、ファイルの最終更新日時を使って最近の順に並べます。

**フォルダーとセッション** の横のメニューで、起動日時、フォルダー名、フルパスの昇順または降順に並べ替えられます。初期設定は起動日時の新しい順で、選んだ順序は次回の起動時も保持されます。サイドバーにはフォルダー名の下にパスが表示されます。長いパスが省略されているときは、ポインターを重ねると全体を確認できます。

### アカウントのタブ

ランチャー上部の **＋** を押し、タブの名前を入力して **作成してログイン** を選びます。新しいプロファイルで PowerShell とブラウザーの案内に従って Claude Code にログインしてください。途中でログイン画面を閉じた場合は、**ログイン** ボタンからやり直せます。タブには自分で付けた名前が表示されます。

タブを選ぶと、同じウィンドウにそのアカウントのプロジェクト、最近のセッション、実行中のターミナルが表示されます。既定のアカウントは既存の Claude Code の設定を使います。追加のプロファイルは、それぞれの `CLAUDE_CONFIG_DIR` に設定とローカルのセッション履歴を保存します。起動中のターミナルも、すでに開いているターミナルも、元のアカウントで動作を続けます。ログイン、セッションの削除や復元が終わってからタブを切り替えてください。セットアップと修復画面が開いている場合は先に閉じてください。

既定のタブは起動時に指定された設定ディレクトリ、または `~/.claude` を使います。追加のプロファイルでは `%LOCALAPPDATA%\BlsLab\ClaudeLauncher\profiles\<ID>\claude` を使い、Claude Code のログイン情報もここに保存します。CLI のインストール先と Windows のユーザー PATH は各タブで共通です。プロジェクトの設定や組織のポリシーも適用されます。 [Claude Code の複数アカウントでのログイン](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)

セッションのトークン使用量にポインターを合わせると、記録に残った所有者のアカウント ID が一部伏せて表示されます。その ID が一つのプロファイルだけに一致する場合はタブ名も表示します。手掛かりがアーティファクトの操作履歴だけの場合、記録がない場合、ID が一致しない場合は、所有者を推定しません。

### ローカル履歴の削除と復元

フォルダーの並べ替えメニュー横にある **管理** で、複数のプロジェクトやセッションにチェックを入れられます。個別の会話を選ぶにはプロジェクトを展開します。プロジェクト自体を選ぶと、検索で非表示のものを含め、そのフォルダーに保存されたセッションがすべて対象になります。1 件だけなら行の **⋯** メニューを開くか、キーボードで行にフォーカスして **Delete** を押してください。確認画面にフルパスと件数が表示されます。使用中または起動中の項目は先にターミナルを閉じてください。

プロジェクトを削除するとランチャーの一覧から消え、ローカルの会話記録は **ランチャーのゴミ箱** に移ります。セッションがないプロジェクトも削除できます。作業フォルダーとファイル、別のプロジェクトとして表示されるサブフォルダー、プロンプト履歴、個別のサブエージェントログ、クラウドのデータは残ります。ランチャーを再起動した後も **管理 → ランチャーのゴミ箱** から復元できます。一括で移動した項目はまとめて復元します。同じ場所にファイルがある場合、上書きせずに停止します。

Claude がセッションごとに作成する一時作業用の `scratchpad` フォルダーや、サブエージェントと識別されたセッションは一覧に表示しません。

### トークン使用量

フォルダーには、検索で非表示になったセッションも含めた記録上のトークン合計が表示されます。セッションの合計はキャッシュの読み書きを含む入力トークンと出力トークンを足した値です。集計対象はローカルのメインの会話記録で、別ファイルのサブエージェントの使用量やプロバイダーの請求情報は含みません。

**コンテキスト**には直近に記録されたコンテキストのトークン数と、ウィンドウに占める割合が表示されます。`≈` はモデルの既定のウィンドウサイズから推定した割合、ダッシュは不明な値、`≥` は一部の記録から算出した合計です。圧縮の回数は圧縮が記録されたセッションにだけ表示されます。千単位は K、百万単位は M で表します。使用量にポインターを重ねると正確な数値を確認できます。

## 表示設定

Windows のタイトルバーをドラッグするとサイドバーを移動できます。サイズを変えるには、ウィンドウの辺や角をドラッグします。タイトルバーの × または Alt+F4 でランチャーを終了できます。次回の起動時に、前回のモニター、位置、サイズが復元されます。

ウィンドウを画面の左端または右端に固定すると、サイドバーとして使えます。**表示設定** ではダークモード、文字サイズ（85～125%）、ウィンドウの不透明度（60～100%）を変更できます。設定はメイン画面とサイドバーで共通で、次回の起動時にも引き継がれます。画面の言語は英語、韓国語、中国語（簡体字）、日本語から選べます。

## ソースからのビルド

.NET 10 SDK をインストールした Windows で、リポジトリのルートから目的のエディションのコマンドを実行します。

```powershell
# フル版
dotnet publish src/ClaudeLauncher.csproj -c Release -r win-x64 -p:PublishProfile=Windows-x64

# インストール・修復専用 Mini
dotnet publish src/Mini/ClaudeRepairMini.csproj -c Release
```

出力先は `artifacts/publish/win-x64/` です。フル版は `ClaudeLauncher.exe`、Mini は `ClaudeRepairMini.exe` として生成されます。
