# Claude Code 런처

[English](README.md) · **한국어** · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

이 런처를 쓰면 Windows에서 Claude Code CLI를 쉽게 설치하거나 복구하고, 이전 세션을 열어 작업을 이어갈 수 있습니다.

1. **Claude Code CLI 자동 설치·복구**

   처음 쓸 때는 CLI를 설치하고, 실행에 문제가 생기면 8단계로 원인을 점검합니다. 해결 방법을 확인하고 승인하면 런처가 선택한 조치를 적용합니다.
2. **로컬 Claude Code 세션 관리·재개**

   런처에서 이 PC에 저장된 Claude Code 대화를 작업 폴더별로 찾을 수 있습니다. 세션을 선택하면 해당 폴더에 PowerShell이 열리고 CLI에서 대화를 이어갑니다.

## 설치 · 복구

기본 창 상단이나 사이드바 왼쪽 아래에서 **설치 · 복구**를 누르면 검사가 시작됩니다. 결과는 **설치 필요**, **이상 있음**, **이상 없음** 중 하나로 표시됩니다. 문제가 있으면 빨간색으로 강조합니다.

고칠 수 있는 문제가 있으면 런처가 원인과 권장 조치 한 가지를 보여주고 진행할지 묻습니다. **예**를 누르면 해당 작업을 실행하고, **아니요**를 누르면 변경하지 않습니다. 직접 로그인하거나 관리자에게 문의해야 할 때는 화면에 다음 할 일이 나옵니다. 검사 근거가 궁금하면 **전체 검사 결과**를 펼쳐 여덟 단계의 세부 내용을 확인하세요.

| 단계 | 무엇을 확인하나요? | 문제가 있으면 어떻게 하나요? |
|---|---|---|
| 1. PC 환경 | Windows 빌드·아키텍처, Windows PowerShell 버전과 실행 경로, 사용자 폴더의 공백·비ASCII 문자를 확인합니다. | x64 실행 환경과 PowerShell 경로를 확인합니다. 사용자 폴더에 한글이나 공백이 있다는 사실만으로 오류로 판단하지 않습니다. |
| 2. 실행 파일 | 설치 경로, 실행 파일의 서명과 버전, 업데이트 도중 남은 `.new.*`·`.old.*` 백업과 이전 버전 파일을 확인합니다. | 검증된 백업이 있으면 복원을 먼저 제안합니다. 쓸 수 있는 백업이 없으면 공식 PowerShell 설치 프로그램을 사용합니다. 파일 교체를 위해 Claude를 닫아야 하면 해당 프로세스의 PID를 확인하세요. 종료하면 그 세션의 작업이 끊깁니다. |
| 3. PATH | 현재 런처가 쓰는 PATH, Windows에 저장된 사용자·시스템 PATH, 실제로 찾아낸 CLI 위치를 대조합니다. | 검증된 설치 폴더가 빠졌으면 사용자 PATH에 추가합니다. 이미 등록돼 있으면 런처의 PATH를 새로고쳐 여기서 여는 PowerShell에 반영합니다. |
| 4. 중복 설치와 명령 충돌 | 같은 이름으로 잡히는 실행 파일, npm 전역 패키지, WindowsApps 별칭, 예전 설치 폴더 `.claude\local`을 확인합니다. | 정상 설치가 먼저 실행되도록 사용자 PATH 순서를 바꿀 수 있습니다. 중복 npm 패키지 제거와 구형 설치 파일 삭제는 별도 작업입니다. 구형 설치를 정리할 때는 확인 화면에 나열된 일반 파일만 삭제합니다. |
| 5. PowerShell 실행 정책 | npm으로 설치한 PowerShell 스크립트가 현재 정책에 막히는지, 조직에서 관리하는 정책이 있는지 확인합니다. | 사용자 범위에서 해결할 수 있을 때만 `CurrentUser`의 실행 정책을 `RemoteSigned`로 바꿀 수 있습니다. 조직 정책이 적용된다면 관리자에게 문의하거나 네이티브 CLI를 사용합니다. |
| 6. 인증·인증서·Git·프록시 | `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`의 설정 범위, `NODE_EXTRA_CA_CERTS`의 인증서 파일, `CLAUDE_CODE_GIT_BASH_PATH`의 셸 경로, Git 설치와 프록시 설정을 확인합니다. 자격 증명과 프록시 주소의 실제 값은 화면에 표시하지 않습니다. | 회사·교육용 설정은 용도를 확인하세요. 필요 없어진 사용자 변수는 개별 삭제하고, 잘못된 Git Bash 경로는 발견한 셸 경로로 수정할 수 있습니다. 시스템 변수나 관리자가 지정한 값은 해당 관리자에게 확인합니다. |
| 7. 네트워크 | 다운로드 응답과 Claude 웹사이트 연결을 확인합니다. API 키를 설정한 경우에는 기본 API 서버 연결도 확인합니다. | 실패한 서버와 오류를 보고 인증서, 프록시, 방화벽 또는 네트워크 연결을 확인합니다. API 서버에서 HTTP 응답을 받은 것은 서버에 닿았다는 뜻이며, 로그인 성공 여부는 빠른 진단에서 따로 확인합니다. |
| 8. 업데이트 정리 | `claude.exe.old.*`, `.new.*`, `.broken.*` 파일, `.claude\downloads`의 캐시, 현재 계정의 자동 업데이트 설정을 확인합니다. | 잔여 파일과 다운로드 캐시는 각각 대상 목록을 확인한 뒤 삭제합니다. 업데이트 잔여 파일을 정리할 때 가장 최근의 old 백업은 남겨 둡니다. 네이티브 설치에서 업데이트 손상 흔적이 있어 자동 업데이트를 끄기로 했다면 이후에는 직접 업데이트해야 합니다. |

**`~/.local/bin/claude.exe`가 사라졌다면** 런처는 먼저 다른 경로에 정상 설치본이 있는지 확인합니다. 있으면 그 설치본의 PATH를 점검합니다. 실행 파일이 없고 복원 가능한 백업이 있으면, 런처가 검증된 백업 하나를 골라 원래 경로에 복원할지 묻습니다. 쓸 수 있는 백업이 없으면 Anthropic의 공식 PowerShell 설치 프로그램으로 재설치할지 묻습니다.

기본 점검 대상은 `downloads.claude.ai`와 `claude.ai`입니다. 런처 환경에 `ANTHROPIC_API_KEY` 값이 있고 기본 API 주소를 쓸 때만 `api.anthropic.com`에 키 없이 접속합니다. 회사에서 프록시나 자체 CA 인증서를 쓴다면 네트워크 담당자와 검사 결과를 확인하세요. [Anthropic의 네트워크 설정 안내](https://code.claude.com/docs/en/network-config)

### 설정 파일, Defender 및 복구 이력

6단계에서는 `~/.claude.json`과 `~/.claude/settings.json`을 UTF-8 JSON으로 읽습니다. 파일이 없어도 정상입니다. 문법 오류가 있으면 행과 열을 알려줍니다. 빠진 쉼표 하나를 넣거나 끝에 남은 쉼표 하나를 지워 파일 전체가 유효해지면 그 수정만 제안합니다. 그 밖에는 형식이 맞는 백업에서 손상된 부분을 복원합니다. 파일 전체를 교체해야 하면 미리보기에서 그 범위를 알려줍니다. 민감한 값을 가린 변경 내역과 원본 보관 경로를 확인한 뒤 승인하세요.

설정 복구를 되돌리면 JSON 오류가 있던 원래 파일로 돌아갑니다. 런처는 복구된 파일과 따로 보관한 원본의 해시를 각각 이력과 대조합니다. 어느 한쪽이라도 달라졌으면 되돌리기를 중단합니다.

실행 파일이 사라졌다면 2단계에서 알려진 설치 경로와 일치하는 Microsoft Defender 격리 기록을 확인합니다. 기록을 읽지 못했거나 일치하는 기록이 없으면 격리는 가능한 원인으로만 표시됩니다. **보호 기록**을 열어 Windows 보안에서 해당 항목을 확인하고 처리할 수 있습니다.

8단계에서는 런처가 꺼 둔 자동 업데이트 설정을 원래대로 돌릴 수 있습니다. 복구 이력에서 런처가 바꾼 값과 현재 값이 일치해야 합니다. 이전부터 사용자 계정에 설정된 `DISABLE_AUTOUPDATER`도 시스템·프로세스·조직 정책과 충돌하지 않으면 별도 승인으로 해제할 수 있습니다.

복구 이력은 `%LOCALAPPDATA%\ClaudeCodeSetupDiagnostics\repair-history`에 현재 Windows 계정용 DPAPI로 암호화해 저장합니다. PATH 변경, 사용자 실행 정책, 업데이트 설정, 버전이 기록된 npm 패키지 제거는 현재 상태를 확인한 뒤 되돌릴 수 있습니다. npm 재설치에는 기록된 버전과 설치 위치, 검증된 도구, 네트워크 연결이 필요합니다. 파일 삭제와 프로세스 종료는 이력에서 확인할 수 있지만 되돌릴 수는 없습니다.

### 설치와 로그인

- 설치 전에 공식 PowerShell 설치 명령과 WinGet으로 전환하는 조건을 보여줍니다. **예**를 한 번 누르면 안내된 조건에서 WinGet을 사용하는 것까지 승인합니다.
- 로그인이 필요하다는 안내에서 **예**를 누르면 별도 PowerShell 창이 열립니다. 런처가 검증한 CLI로 `claude auth login`을 실행합니다. 브라우저에서 로그인을 마치거나 로그인 창을 닫아 취소하면 런처가 현재 계정 상태를 다시 확인합니다.
- Git for Windows는 선택 사항입니다. Git이 없고 Microsoft가 등록한 WinGet을 찾으면 6단계에서 현재 Windows 계정에 `Git.Git` 설치를 제안합니다. 설치 대상을 확인하고 별도로 승인하세요. 설치를 승인하면 WinGet 원본 및 Git 패키지 약관에도 동의합니다.
- 대화를 열다가 설치·복구로 들어왔다면, 복구 후 빠른 진단이 정상인지 확인하고 처음 선택한 폴더와 세션으로 돌아갈 수 있습니다.

| 검사나 복구가 멈춘 경우 | 확인할 내용 |
|---|---|
| 작업 폴더를 열 수 없음 | 폴더를 옮겼거나 삭제했는지 확인하고 **폴더 찾아보기**로 현재 위치를 선택하세요. |
| PowerShell에서 다른 설치본을 찾음 | 같은 폴더에서 `Get-Command claude -All`로 실행 순서를 확인하세요. 런처는 네이티브 실행 파일의 Authenticode 서명과 게시자 `Anthropic, PBC`를 검증한 뒤 버전을 조회합니다. |
| 설치가 멈춘 것처럼 보임 | 내려받는 동안 화면에 출력이 없어도 설치가 진행될 수 있습니다. 런처는 설치 프로그램의 출력과 다운로드 파일의 변화를 함께 살핍니다. 둘 다 5분 연속 없고 기존 설치 프로세스를 안전하게 종료한 경우에만 WinGet으로 계속합니다. 설치 오류나 취소, 설치 후 검증 실패로 끝난 경우에는 WinGet을 실행하지 않습니다. |
| 검사용 PowerShell이 응답하지 않음 | 빠른 진단은 PowerShell 검사 한 번에 최대 25초를 기다립니다. 팝업의 오류와 종료 코드를 확인하고 해당 폴더에서 PowerShell을 열어 보세요. |

새로 설치하거나 재설치할 때 런처는 사용자 승인을 받은 뒤 PowerShell에서 다음 명령을 실행합니다. [Anthropic 공식 설치 안내](https://code.claude.com/docs/en/setup#install-claude-code)

```powershell
irm https://claude.ai/install.ps1 | iex
```

## GUI에서 세션 관리하기

1. Windows x64용 `ClaudeLauncher.exe`를 엽니다. .NET 데스크톱 런타임은 실행 파일에 포함돼 있습니다.
2. 열려 있는 터미널로 돌아가려면 **지금 실행 중 → 이동**을 누릅니다. 이전 대화는 **최근 실행한 세션**에서 고릅니다. 최근 목록에는 최대 5개가 표시됩니다.
3. 오래된 대화는 **폴더 및 세션**에서 폴더를 펼치거나 세션 이름을 검색해 엽니다. 선택한 대화는 해당 폴더에서 `claude --resume <세션 ID>`로 이어집니다. 새 대화는 폴더에서 **새 세션 시작**을 누르거나 다른 폴더 경로를 입력해 시작합니다.
4. 기록을 읽지 못한 폴더는 **CLI에서 이 폴더의 세션 선택**을 누르면 PowerShell에서 `claude -r` 선택기가 열립니다. 폴더를 직접 지정하려면 트리를 우클릭하세요.

대화 제목과 폴더는 Claude 설정 디렉터리의 `projects` 아래에서 세션 JSONL을 읽어 표시합니다. 런처에 실행 이력이 없는 대화는 파일의 마지막 수정 시각으로 최근 순서를 정합니다.

**폴더 및 세션** 옆의 정렬 메뉴에서 최근 실행 시각, 폴더 이름, 전체 경로를 기준으로 순서를 바꿀 수 있습니다. 각 기준은 오름차순과 내림차순을 지원합니다. 처음에는 최근 실행한 폴더가 맨 위에 오고, 순서를 바꾸면 다음 실행 때도 유지됩니다. 사이드바에서는 폴더 이름 바로 아래에 경로가 보입니다. 경로가 길어 말줄임표가 나오면 마우스를 올려 전체 경로를 확인하세요.

### 로컬 기록 제거와 복원

폴더 정렬 옆 **관리**를 누르면 여러 프로젝트와 세션을 체크할 수 있습니다. 프로젝트를 펼치면 대화 하나씩 고를 수 있고, 프로젝트 자체를 체크하면 검색에서 가려진 세션까지 그 폴더의 저장된 세션이 모두 포함됩니다. 한 항목만 옮기려면 행의 **⋯** 메뉴를 열거나 키보드로 행을 선택한 뒤 **Delete**를 누르세요. 확인 창에서 전체 경로와 세션 수를 보고 결정합니다. 선택한 프로젝트나 세션이 터미널에서 열려 있거나 시작 중이면 먼저 닫아야 합니다.

프로젝트를 제거하면 런처에서 해당 항목이 사라지고 로컬 대화 기록은 **런처 휴지통**으로 이동합니다. 세션이 없는 프로젝트도 제거할 수 있습니다. 실제 작업 폴더와 파일, 별도 프로젝트로 표시되는 하위 폴더, 프롬프트 이력, 별도 서브에이전트 기록, 클라우드 데이터는 그대로 남습니다. 런처를 다시 열어도 **관리 → 런처 휴지통**에서 복원할 수 있습니다. 함께 옮긴 항목은 한꺼번에 복원하며, 같은 위치에 파일이 있으면 덮어쓰지 않습니다.

Claude가 세션마다 만드는 임시 `scratchpad` 폴더와 서브에이전트로 식별된 기록은 세션 목록에서 제외합니다.

### 토큰 사용량

폴더에는 검색으로 숨겨진 세션까지 포함해 기록된 토큰 합계가 표시됩니다. 세션의 합계는 캐시 읽기·쓰기를 포함한 입력 토큰과 출력 토큰을 더한 값입니다. 이 수치는 로컬의 주 대화 기록을 집계한 것으로, 별도 파일에 저장된 서브에이전트 사용량과 서비스 청구 내역은 포함하지 않습니다.

**컨텍스트**에는 마지막으로 기록된 컨텍스트의 토큰 수와 창에서 차지하는 비율이 나옵니다. `≈`가 붙은 비율은 모델의 기본 창 크기로 추정한 값입니다. 확인할 수 없는 값은 대시로, 일부 기록만 합산한 값은 `≥`로 표시합니다. 대화 압축이 기록된 세션에는 압축 횟수도 보입니다. 천 단위는 K, 백만 단위는 M으로 줄여 쓰며, 사용량에 마우스를 올리면 정확한 수치를 볼 수 있습니다.

## 화면 설정

런처를 다시 실행하면 사이드바가 마지막으로 사용한 모니터의 같은 쪽에 같은 크기로 열립니다. 화면 안쪽을 향한 테두리를 끌면 너비를, 아래쪽 테두리를 끌면 높이를 바꿀 수 있습니다. 안쪽 아래 모서리를 끌면 둘 다 조절됩니다. 사이드바의 닫기 버튼을 누르면 런처가 종료됩니다.

창 상단에서 왼쪽 또는 오른쪽 고정을 선택하면 사이드바로 쓸 수 있습니다. **화면 설정**에서는 다크 모드, 글자 크기(85~125%), 창 불투명도(60~100%)를 조절합니다. 기본 창과 사이드바가 같은 설정을 쓰며, 다음 실행 때도 유지됩니다. 한국어, 영어, 중국어 간체, 일본어를 지원합니다.

## 소스에서 빌드하기

.NET 10 SDK가 설치된 Windows에서 저장소 루트를 열고 실행합니다.

```powershell
dotnet publish src/ClaudeLauncher.csproj -c Release -r win-x64 -p:PublishProfile=Windows-x64
```

실행 파일은 `artifacts/publish/win-x64/ClaudeLauncher.exe`에 생성됩니다.
